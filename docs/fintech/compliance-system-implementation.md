# Compliance System Implementation

## When To Use This

- The work is driven by regulation, policy, or audit findings.
- The system must preserve evidence and traceability.
- The release cannot proceed without compliance sign-off.

## Workflow

1. FDE captures the mandate and the deadline.
2. FDE writes the PRD with compliance constraints and non-goals.
3. Risk Officer validates the PRD and the assumptions.
4. FDE defines the audit architecture, retention rules, and submission flow.
5. Engineering writes specs for logging, reporting, and control enforcement.
6. Compliance clears the readiness gate.
7. Build with auditability as a hard requirement.
8. Run the retrospective against the mandate, not just the implementation.

## Outputs

- PRD
- Architecture spine
- Epic specs
- Compliance checklist
- Retrospective verdict
