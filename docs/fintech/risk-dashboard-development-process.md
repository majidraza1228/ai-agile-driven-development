# Risk Dashboard Development Process

## When To Use This

- The risk team needs visibility into exposure, concentration, VaR, or thresholds.
- The dashboard must support daily decision-making.
- The UI must be understandable to non-engineers.

## Workflow

1. FDE collects the risk questions the dashboard must answer.
2. FDE writes or updates the PRD with operational requirements.
3. Risk Officer validates the PRD.
4. FDE and Architect define the data flow and aggregation layers.
5. UX defines the dashboard layout, alerts, and interaction model.
6. Engineering writes specs for the data and UI epics.
7. Compliance signs off on the readiness gate.
8. Build, integrate, and validate with real data.
9. Run the retrospective after the risk team uses the dashboard live.

## Outputs

- PRD
- UX notes or design file
- Architecture spine
- Epic specs
- Compliance checklist
- Retrospective
